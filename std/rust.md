# Rust 编码标准

本文件只补充 Rust 特有规则。通用工程、安全、数据库和日志要求分别继承 [general.md](general.md)、[security.md](security.md)、[database.md](database.md) 和 [logging.md](logging.md)。

## 适用基线

0. Edition、最低 Rust 版本和 toolchain 以 `Cargo.toml`、`rust-toolchain` 与发布目标为准。
1. 异步运行时、序列化、错误库和 lint 配置沿用项目已有选择，不默认绑定 Tokio、Serde 或特定 crate。

## 类型与所有权

0. 可见性从最小范围开始，公共类型和 trait 只暴露稳定契约。
1. `Option` 表达缺失，`Result` 表达可恢复失败；只有不变量被证明时才使用 `unwrap` / `expect`。
2. 借用、值传递、`Clone`、`Arc` 和锁根据真实所有权选择，不用复制绕开设计问题。
3. 生命周期标注只表达必要关系；复杂泛型和 trait bound 是审查信号，不设统一数量限制。
4. 状态集合优先用 enum 表达，避免多个 bool 组合出非法状态。

## 错误与资源

0. 错误类型保留稳定分类和 source 链；库与应用可选择不同错误表示，但边界必须明确。
1. `?` 用于传播时补充责任边界需要的上下文，不在每层重复记录。
2. RAII 和 `Drop` 覆盖资源释放；需要显式确认提交或关闭结果时不能只依赖析构。
3. 可能 panic 的公共 API 记录前置条件；不可信输入不得轻易触发 panic。
4. `unsafe` 块保持最小，并记录调用者与实现必须共同维护的安全不变量。

## 异步与并发

0. Future 必须被等待、返回或交给有生命周期管理的任务集合，避免静默丢弃。
1. 不持有同步锁跨越 `.await`；共享状态先评估消息传递、所有权转移或更小锁域。
2. 正确标注和验证 `Send` / `Sync` 边界，FFI 与回调线程模型必须显式说明。
3. 取消、超时和任务 panic 的处理方式沿调用链一致。

## 工具与测试

0. 使用 `cargo fmt`、`cargo clippy` 和项目锁定的工具链；lint 豁免局部化并说明理由。
1. 单元测试与集成测试按公共边界组织；异步测试使用项目运行时提供的测试能力。
2. 涉及内存、并发或 unsafe 时，根据风险使用 Miri、sanitizer、loom 或压力测试。

## 常见陷阱

0. async 代码持有同步锁、借用或大对象跨越 `.await`。
1. `clone`、`collect` 和中间分配掩盖不必要的复制。
2. 忘记自定义资源的关闭结果，或误以为 `Drop` 可以执行可靠异步清理。
3. 字符串按字节与字符索引混淆，切片边界落在非 UTF-8 字符边界。
4. unsafe、FFI 或自引用结构的不变量未被测试和文档共同约束。
