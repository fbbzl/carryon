# 安全标准

安全基线适用于开发、测试和生产环境；环境差异只能改变控制强度，不能取消输入校验、秘密保护和授权边界。

## 信任边界与输入

0. 所有外部输入按来源校验类型、长度、范围、格式和业务权限。
1. 数据库查询使用参数绑定或等效安全 API，不拼接不可信输入。
2. HTML、URL 等文本在输出点按目标上下文编码；OS 命令优先使用无 Shell 的参数 API 和允许清单，不用字符串转义替代安全边界。
3. 文件、路径、URL 和反序列化输入必须限制允许范围，并防止路径遍历、SSRF 和不可信类型实例化。
4. 接受文件上传时，校验大小和真实内容、由服务端生成文件名，并存入不可执行且与静态站点隔离的位置；下载通过受控响应提供。

## 认证与授权

0. 密码使用适合密码存储的慢哈希算法和独立盐，不可逆加密或普通哈希不能替代。
1. Session、Token 和 API Key 具备足够熵，并按风险设置生命周期、吊销和轮换机制。
2. 服务端按主体、资源和动作执行授权；前端隐藏按钮不构成权限控制。
3. 最小权限、二次认证、限流和异常通知根据资产与威胁模型采用，不机械覆盖所有操作。

## 秘密与敏感数据

0. 密钥、密码和 Token 不进入源码、日志、客户端、构建或部署产物、镜像层与构建缓存。
1. 秘密通过项目批准的配置或秘密管理机制注入，并限制读取范围。
2. 凭据和敏感数据跨不可信边界传输时必须使用经认证的加密通道；HTTP 场景应正确验证 TLS 证书。
3. 敏感数据按分类决定存储、脱敏、加密和保留策略；不得无依据扩大采集范围。
4. 日志、错误响应、监控标签和测试数据不得泄露敏感值。
5. 确认凭据泄露后，立即隔离影响范围并吊销旧凭据；闭环证据至少覆盖传播位置清单、旧凭据负向验证、新凭据正向验证、会话与缓存失效、残留介质处置及观察窗口内无再次泄露。

## Web 与会话

0. Cookie 根据部署方式设置 `HttpOnly`、`Secure`、`SameSite` 和合理作用域。
1. 登录、刷新、登出和权限变化必须正确更新服务端会话状态。
2. CSRF、XSS、点击劫持和跨域控制根据实际认证方式与浏览器边界配置。

## 依赖与验证

0. 新依赖检查必要性、维护状态、来源、许可证和已知漏洞；锁定可复现版本。
1. 安全更新按可利用性和暴露面排序，并验证兼容性，不能只追求最新版本。
2. 高风险变更验证恶意输入、越权、凭据失效和失败路径；无法验证的范围作为未关闭风险记录。
3. 安全日志和证据保留期由项目风险、成本和合规要求决定，不设置跨项目固定天数。
4. 高风险安全结论按 `资产 -> 信任边界 -> 攻击路径 -> 控制 -> 验证证据 -> 残余风险与下一行动` 记录；未触及某项时也说明判断依据。
