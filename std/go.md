# Go 编码标准

本文件只补充 Go 特有规则。通用工程、安全、数据库和日志要求分别继承 [general.md](general.md)、[security.md](security.md)、[database.md](database.md) 和 [logging.md](logging.md)。

## 适用基线

0. Go 版本以 `go.mod`、工具链配置和部署目标为准，代码不得使用高于兼容目标的特性。
1. 格式化使用 `gofmt`；导入、lint 和生成工具沿用仓库配置。

## 包与接口

0. 包保持单一目的，名称简短且不重复上层语义；避免导出不需要的标识符。
1. 接口由消费者按需要定义，保持小而稳定；不为“可测试”预先给所有类型造接口。
2. 依赖和运行配置显式传入，避免通过全局变量或带业务副作用的 `init` 隐式初始化。
3. 切片、Map 和指针的所有权约定要清楚；可能修改调用方数据时在契约中说明或复制。

## 错误与资源

0. 错误必须处理或返回；仅在责任边界记录，不能用“至少 log”代替传播或恢复。
1. 使用 `%w` 包装需要保留原因的错误，并用 `errors.Is` / `errors.As` 判断稳定语义。
2. `panic` 只用于无法继续的编程不变量或启动失败；请求级业务错误通过 `error` 返回。
3. `defer` 用于清理时检查资源获取是否成功，并处理重要的关闭或提交错误。

## 并发与取消

0. `context.Context` 沿调用链显式传递，不存入长期对象或使用全局 Context。
1. 每个 goroutine 都必须有所有者、退出条件和错误去向，避免泄漏和失控后台任务。
2. Channel 的缓冲、关闭方和消费停止条件必须明确；只由发送方或所有者关闭。
3. HTTP 客户端、服务端和外部调用设置适合场景的超时，并传播取消信号。

## 工具与测试

0. 使用标准库测试框架和项目已有断言工具；多输入场景优先 table-driven tests。
1. 并发代码运行 `go test -race`；基准只在有性能问题或预算时编写。
2. `go vet`、lint 和生成代码命令应与仓库工具版本一致。

## 常见陷阱

0. 兼容 Go 1.22 之前循环语义的模块，或循环外预声明迭代变量时，goroutine 闭包捕获复用变量；另需避免未等待退出或向无人接收的 Channel 阻塞。
1. nil Map 写入、nil interface 与带类型 nil 混淆。
2. 切片 append 后共享底层数组，导致调用方数据被意外修改。
3. 忽略错误、重复包装丢失分类，或在多层重复记录同一错误。
4. 复用默认 `http.Client` 而没有满足场景的超时与连接配置。
