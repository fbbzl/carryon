# API 设计标准

本标准面向 HTTP API；RPC、消息协议或既有公共契约以项目约定为准。

## HTTP 语义

0. 资源型接口优先使用名词路径和 HTTP Method 表达操作；确属命令语义时可使用清晰的动作端点。
1. 状态码必须与实际结果一致；`204 No Content` 不返回响应体。
2. 查询参数用于过滤、排序和分页，字段含义与默认值保持稳定。
3. 缓存、安全方法和幂等语义不得与网关、客户端或文档声明冲突。

## 请求与响应

0. 成功响应是否包装由项目契约决定；不得为了统一外壳破坏 HTTP 状态语义。
1. 错误响应使用稳定、机器可读的错误码，并提供适合调用方的说明；不得泄露内部堆栈或敏感数据。
2. 时间明确格式和时区，跨系统传输优先使用 ISO 8601。
3. 金额使用能精确表达业务精度的格式，例如最小货币单位整数或十进制定点字符串；禁止二进制浮点误差进入结算。
4. 枚举、分页、批量上限和空值语义必须在契约中明确。
5. 服务端必须校验请求；静态类型和前端校验不能替代运行时校验。

## 幂等与并发

0. 遵守所选 HTTP 方法的幂等语义。
1. 对支付、创建、回调、重试或重复提交等高风险写操作，使用业务唯一键、幂等键或等效机制。
2. 明确并发写入的冲突策略，不用“最后写入获胜”掩盖数据不变量。

## 兼容与演进

0. 版本机制由项目选择 URL、Header、媒体类型或不显式版本化；同一 API 保持一致。
1. 不兼容变更必须提供新契约和迁移路径，废弃窗口根据真实消费者与发布节奏确定。
2. 契约变化要识别调用方、SDK、缓存、事件、文档和测试的影响。

## 认证与可靠性

0. 认证机制服从项目安全架构；授权必须在服务端按资源和动作校验。
1. 凭据不得硬编码在客户端或公开配置中，Token 生命周期与吊销能力按风险设计。
2. 外部调用显式设置超时；限流、重试、熔断和降级只在风险与容量需要时采用，并保证组合行为一致。

## 文档与验证

0. 文档至少说明用途、权限、幂等性、请求、响应、错误和兼容约束。
1. 项目使用 OpenAPI 或其他契约工具时，以可执行契约为准并与实现同步。
2. 关键接口验证正常、异常、权限、重复请求、并发和兼容路径。
