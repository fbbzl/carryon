# 克隆并初始化项目

完成条件是 Git clone 成功，且在新仓库根目录执行 `codegraph init` 成功。只完成 clone 时，应报告部分完成。

## 输入与边界

- 使用用户提供或项目中已有的仓库地址，不猜测 URL。目标目录未指定时，按当前工作区和仓库名称确定，并在执行前说明绝对路径；存在歧义时再询问。
- 目标目录已存在且非空时停止，不覆盖、删除或自动改用该目录。若用户明确要求继续已有副本，先核对仓库身份、工作区状态和初始化记录，再确定剩余步骤。
- 只使用用户指定的分支、标签和 clone 选项；未指定时使用 Git 默认行为，不自行添加浅克隆、递归子模块或依赖安装。
- 不自动安装或升级 CodeGraph，不修改全局配置，不自动提交、push 或启动项目。
- `codegraph` 是默认初始化项。其他 MCP 只有在项目根目录存在明确的项目声明、当前会话工具已可用且初始化不需要猜测凭据或外部目标时，才可作为可选初始化项；未声明的 MCP 不自动探测、安装或配置。

## 执行流程

1. 读取当前工作区适用的 `AGENTS.md` 和本地规范；若当前目录属于 Git 仓库，先检查 `git status`。确认目标绝对路径和 `git`、`codegraph` 命令可用。缺少工具时报告阻塞和已完成阶段，不擅自换用同名包或远端安装脚本。
2. 在目标父目录执行 `git clone`，将地址和目标目录作为独立参数传入。检查退出码；失败时停止，不在残留目录执行初始化，也不自动删除残留内容。
3. clone 成功后，读取新仓库适用的 `AGENTS.md` 和本地初始化说明。在新仓库根目录执行 `git status`，核对实际仓库位置和用户指定的版本。若新仓库规则与初始化要求冲突，先报告冲突。
4. 将进程工作目录明确设为新仓库根目录，执行 `codegraph init`。不能在父目录、原工作区或仅凭终端之前的 `cd` 状态执行。遇到交互选项时依据用户要求和本地说明选择；影响范围不明时询问，不猜选项。
5. 检查初始化退出码和输出中的成功或失败信息，再检查 `git status --short`，报告初始化产生的改动。若输出提供了明确的后续验证方式，按本地说明验证；不猜测 CodeGraph 的配置文件名或检查命令。
6. 检查项目本地规范或明确的 MCP 声明文件。对声明的可选 MCP，先确认其命令、版本、工作目录、权限和失败影响；只有这些信息完整且不会要求猜测凭据时才执行初始化。数据库、GitHub/GitLab、Docker/Kubernetes 和知识库类 MCP 默认跳过，除非项目声明和用户授权都明确覆盖它们。

## 失败与交付

初始化失败时保留已克隆仓库，报告“clone 成功，codegraph init 失败”，附经过脱敏的失败原因与目标路径。先检查部分生成的文件和失败原因；仅在原因已消除且确认重试不会覆盖已有内容时重试，不循环运行初始化。

最终报告仓库绝对路径、实际分支或提交、clone 结果、`codegraph init` 结果、可选 MCP 的跳过或初始化结果和待处理事项。日志与地址中不得暴露凭据。项目初始化成功不等于当前会话已具备对应 MCP 工具；仅在会话工具确实可用时声明 MCP 可用。
