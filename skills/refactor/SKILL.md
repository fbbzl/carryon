# refactor

在不改变已确认外部行为的前提下，完成高技术含量、范围受控、可回退的实现重构。该 Skill 只服务于 `dev` 的实现工作，不替代 `openspec` 的重大方案确认、`cr` 的审查结论或 `qa` 的测试结论。

## 适用条件

- 目标是拆分高耦合模块、提取稳定边界、消除架构债、降低圈复杂度、收紧类型/状态模型、移除重复路径或隔离副作用，且外部行为不变。
- 已明确行为不变量、调用方、被调用方、数据读写、权限边界、错误语义、并发/事务语义和可回退路径；缺任一关键证据时先完成影响分析。
- 若涉及新行为、缺陷修复、公共契约变化、数据迁移、权限变化、跨服务协议变化或性能目标变化，回到 `dev` 常规实现流程；新模块或重大边界变化先使用 `openspec`。

## 重构设计

1. 写清重构目标、行为不变量、技术债成因、期望结构和不做事项；把“更好看”改写成可验证目标，如依赖方向、重复路径、状态数量、边界稳定性或复杂度下降。
2. 画出影响边界：入口、出口、公共契约、持久化读写、缓存/MQ、事务、锁、权限、日志/指标和失败路径；标出哪些只允许搬移，哪些允许改写。
3. 选择策略：提取纯函数、引入端口/适配器、拆分状态机、分离命令查询、收敛 DTO/类型、替换继承为组合、隔离副作用或压平循环依赖；只选能直接服务目标的策略。
4. 设计等价证明：对每个外部可观察点说明重构前后输入、输出、错误、时序、副作用、数据不变量和兼容窗口如何保持一致。

## 实施纪律

- 先建立保护网：读取现有测试、构建命令、静态检查、调用链和日志证据；`dev` 可以运行构建/静态检查或现有测试作为证据，但不得生成/维护测试资产或输出 QA 结论。
- 切片必须小到可独立回退：优先“移动不改写 -> 改名/提取 -> 替换调用 -> 删除旧路径”的顺序；格式化、批量重命名和语义调整分开。
- 每个切片只改变一种结构关系；涉及公共入口时保留兼容门面或适配层，直到调用方全部迁移且 `cr/qa` 证据允许删除。
- 对循环依赖、共享可变状态、隐式全局配置、时间/随机数/IO、事务边界和缓存失效要单独写风险说明；无法证明等价时停止扩大范围。

## 等价门禁

- 公共 API、权限、错误码、日志安全、数据库语义、事务提交点、幂等性、缓存键、MQ 消息、配置名和运行入口不得静默改变。
- 删除代码前必须证明没有仍在使用的入口、配置、序列化字段、迁移依赖或运行脚本；证据不足时保留兼容层并标记退出条件。
- 构建、静态检查和 diff 复核只能证明实现证据，不等同于审查或测试通过。
- AI 辅助重构必须由 `dev` 人工复核调用链、差异和不变量；不能把 AI 的等价判断直接交付。

## 交付

- 向 `cr` 交付：重构目标、行为不变量、策略选择、直接/受影响文件、依赖边界变化、等价证据、构建/静态检查结果、未验证风险和建议审查重点。
- 向 `qa` 交付输入：受影响外部行为清单、应保持不变的场景、边界条件和未验证范围；是否生成或执行测试由 `qa` 决定。
- 退出时必须能说明：目标是否完成、保持的行为、实际改动文件、可回退点、残余耦合、已知风险和下一步。

- 不生成或执行测试，不作代码审查、验收或发布结论。
- 不以“重构”为名扩大需求、删除兼容行为或跳过迁移/恢复设计。
- 当行为等价性无法从当前证据证明时，冻结争议范围，标记未验证范围并交给 `cr`、`qa` 决定后续验证。
