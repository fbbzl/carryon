# 从代码生成 API 文档

根据当前项目代码生成可供调用方使用的 Markdown API 文档。将用户提供的参考文档当作信息架构和呈现粒度的样例，不当作当前项目的字段、认证、分页、错误码或响应契约。

## 不可变约束

- 不绑定、默认或补全任何通用请求、通用响应、成功标识、错误码、数据包裹层或分页字段。`page`、`limit`、`offset`、`cursor`、`data`、`code` 等名称都不能因习惯或参考文档而写入。
- 每个接口独立从当前项目的证据推导方法、路径、参数位置、字段、必填性、类型、默认值、约束、响应形状与分页语义。相同路径组中的接口也不能互相假设。
- 只有当代码明确证明多个接口共享同一契约时，才在“通用约定”中抽取它；通用段必须说明适用范围，并且接口段的差异优先。
- 未能从代码、项目内规范或已验证测试确定的内容，标注“未确认”，同时指出缺失的证据；不编造地址、认证方式、字段说明、示例值、默认值或错误响应。
- 不写入密钥、令牌、密码、真实个人信息、内部主机名或其他敏感值。示例使用显然虚构的安全占位值，且不借此创造未证实的字段。

## 证据收集

先阅读工作区的 `AGENTS.md`、`std/` 和现有 API 文档，确定本地规则、受众、输出位置与已有术语。再按下列优先级检查证据，并记录每个接口的来源位置以供复核：

1. 路由或控制器声明确定 HTTP 方法、路径、Path 参数和请求内容类型。
2. 请求 DTO、Schema、validator、绑定逻辑和业务分支确定字段、位置、类型、必填性、默认值、互斥或条件约束。
3. 响应 DTO、序列化器、响应构造逻辑及异常处理器确定实际响应形状、状态码和错误语义。
4. 路由集成测试、契约测试、已验证的示例与项目内规范用于交叉验证，不能用来覆盖更高优先级的实现证据。

若声明与实现冲突，以运行时实际序列化/返回路径为准，并在文档中简洁标注冲突。若代码在不同分支按条件返回不同形状，分别记录触发条件，不能压缩成一个臆测的统一结构。

## 生成流程

1. 先界定文档范围：用户指定的模块、路由目录或全项目。范围未指定时，按项目现有公开路由与已有文档边界推断，并在文档开头写明实际覆盖范围。
2. 枚举接口后逐一建立证据卡：方法、路径、认证、输入来源、请求字段、响应字段、成功/失败路径、示例可用性与源码位置。
3. 先完成字段表，再根据同一证据生成请求和响应示例。示例必须与字段表和实际嵌套层级一致；动态键、透传对象或开放结构必须如实标示，不展开猜测字段。
4. 只有确实存在分页时记录其位置、参数名称、页码/游标语义、默认值、限制以及返回导航或总数信息。不得将任何分页协议迁移到其他接口。
5. 使用本技能“文档结构”完成文档。保留用户已有且仍正确的内容；只更新已被代码证据证实需要变化的部分。
6. 完成后回查每个接口：路径、方法、参数位置、必填性、类型、默认值、嵌套路径和示例均能在证据卡中找到来源。确认示例 JSON/YAML 或 HTTP 报文语法有效。

## 文档结构

采用参考文档的阅读方式和章节粒度，但不复制其任何具体字段或协议。

```markdown
# <系统或模块> API 文档

> 覆盖范围：<已核实的路由或模块范围>。本文依据 <代码/规范证据> 生成。

## 阅读约定

<必填标记、类型写法、未确认项标记等，仅写已采用的约定>

## 环境与认证

<仅在项目证据存在时写入；否则说明未在范围内确认>

## 通用约定

<仅列出已证明共享、且注明适用接口的契约；没有则省略>

## 1. <接口名称>

### 功能介绍

### 使用约束

### 接口原型

### 请求参数

### 响应参数

### 请求示例

### 响应示例

### 错误与边界情况
```

每个接口的“接口原型”至少列出已证实的 HTTP 方法和路径。请求参数表按实际来源区分 Header、Path、Query、Cookie 或 Body；字段路径使用项目实际的嵌套写法。响应参数表按真实返回对象、数组或动态映射列出字段。只有在代码或测试给出稳定含义时，才为“必选”“默认值”“枚举值”下结论。

“使用约束”和“错误与边界情况”只陈述可验证的前置条件、互斥/依赖规则、状态码或业务错误，不把推测写成契约。无可靠示例时不要造一个，用“未从项目证据获得可安全公开的示例”替代。

## 写作与交付

使用 `technical-writer-voice` 的技术写作要求：结论有来源，机制先于评价，事实、解释和未确认项分开写。然后使用 `humanizer` 的 `technical-writer` 技术语气做表层清理，去除泛化、营销词、重复和聊天式元话语；清理后重新核验所有字段名、代码标识、数值、样例与限定语，不能改变契约含义。

默认输出中文，除非用户指定其他语言。交付时简要说明覆盖范围、证据不足而标为“未确认”的项目，以及实际修改或生成的文件路径。
