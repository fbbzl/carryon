# Consensus Goal

`consensus-goal` 为单个 Codex goal 加入独立反证审查，避免执行者围绕既定方案自证。它不是让两种目标竞争：执行者推进目标，审查者从范围、事实、实现和验证中主动找茬。审查通过只表示本 Skill 的反证审查完成，不替代原 goal 要求的验证、审批或交付门槛。

目标可以涉及代码、文档、配置、测试或其他交付物。是否允许修改由用户的 goal 决定；只要求评估、审阅或报告的 goal 不得修改交付物。

## 输入要求

只要求用户提供一个 **目标**：一句话说明对象、预期结果，以及可用时的验收标准。

例如：将 README 的安装章节更新为当前可运行的安装步骤，且所有命令和链接均可验证。

Skill 可从目标中拆出对象、约束和验收条件；只有缺少对象、预期结果或完成依据时才澄清。

- 未限定证据范围时，使用直接支撑完成结论的现有材料、修改内容和相关验证结果。
- 不因启用本 Skill 获得额外修改或外部操作权限。涉及敏感信息、外部副作用、不可逆操作、权限扩大或高影响对象时，先明确风险、授权和恢复条件；缺一即暂停。
- 交接、验证摘要和最终报告不得包含密钥、密码、Token、个人敏感信息或原始受限数据；必要时仅记录脱敏摘要、证据位置和访问条件。无法安全引用时阻断并请求安全取证路径。

## 角色与权限

执行者和审查者必须由两个独立、真实的 Agent 承担。不得由同一 Agent 顺序模拟两种角色或以角色口吻替代独立审查。

1. **执行者**：读取最新状态，实施目标要求的修改或分析，并验证完成条件。每次修改文件前必须重新读取最新内容。
2. **审查者**：独立寻找遗漏、错误、回归、无依据假设和证据缺口；输出通过结论或带证据的异议与修复要求。**不得修改、写入、覆盖、回滚或删除目标交付物。**

首轮判断前，审查者只能接收 goal、当前基线、交付物状态和验证证据，不接收执行者的推理或预设结论。

执行者的完成判断不等于最终结论。两名 Agent 必须区分事实和推断，引用可复核证据，且不得处理当前目标无关的既有修改。

## 执行与反证协议

固定由执行者先推进，再由审查者独立找茬，随后回到执行者；两者串行循环。仅执行者可修改目标交付物，审查者不得直接修复、绕过执行者或代替执行者写入。每一轮次都必须：

- 读取目标涉及对象的最新状态、前一名代理的改动、验证结果和遗留异议；执行者每次计划修改文件前，必须从磁盘重新读取目标文件的最新内容，不得依据缓存或旧交接直接编辑；
- 独立验证目标是否已经满足完成条件；
- 审查者提出异议时，必须给出可复核的证据、影响和具体修复要求；
- 执行者收到异议后，必须先独立验证问题是否存在。问题成立才可进行最小范围修复并运行相关验证；问题不成立则记录反证与不修改理由，交由审查者复核；
- 审查者只输出审查结论、异议和修复要求，不得因自身判断直接修改目标交付物；
- 使用以下交接字段记录并传递本轮结果：`goal_id`、`round`、`role`、`reference_version`、`environment`、`baseline`（对象与读取时点）、`goal`、`verified_scope`、`unverified_scope`、`changes`、`validation`（方法与结果及观察时间）、`challenges`（证据、影响、修复要求或反证）、`decision`（继续、通过、无进展、阻塞）和 `open_items`。交接缺少与本轮相关字段时，接收方不得据此修改或宣布通过。

在每个完整往返后，双方依据最新证据重新判断目标是否已达成。只有审查者明确接受完成结论、且验证证据可复核时，才能正常结束。

目标交付物、相关依赖、运行环境或完成条件发生变化时，先前与之相关的验证和审查结论自动失效；执行者与审查者必须基于新的 `reference_version` 重新验证。

- 出现一个完整往返没有新的可复核证据或必要修改、事实争议无法由现有证据消解，或需要用户决策、授权、恢复条件或材料时，视为无法继续。
- 无法继续时，立即暂停自动循环并要求用户人工参与；不得继续尝试、猜测或制造通过结论。
- 向用户报告：当前目标、执行与验证结果、审查异议及证据，以及恢复推进所需的最小人工输入，例如补充证据、澄清标准或授权后续修改。
- 用户提供所需输入后，从执行者继续下一轮；用户要求停止时，以未解决结束。

结束或暂停时必须报告“已达成”或“未解决”，列出最终证据、已做改动、未解决异议和最小下一步。不得无限循环，也不得为了完成目标而制造通过结论。

不同目标的结果必须相互独立。不得用一个目标的证据推断另一个目标的状态。
