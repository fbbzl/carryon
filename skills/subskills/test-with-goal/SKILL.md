# test-with-goal

## 适用边界

仅由 `qa` 在已确认需求、实现范围或待复测 Bug 明确时调用。它把一次测试工作收束为一个可验证 Goal，不替代 `qa` 剧本、`survey-corps` 状态机或用户发布授权。

`dev` 维护实现耦合的单元测试；`qa` 独占独立测试策略、集成/API/端到端/回归资产、正式执行、Bug 生命周期和验收结论；`cr` 不执行测试，`dp` 只消费结论。

## 图示对齐

当测试目标涉及多状态路径、数据流或覆盖边界时，可用 Mermaid 或 ASCII 字符图辅助说明；图示不替代测试预言机、执行记录或质量结论。

## Goal 定义

每个 Goal 绑定当前 `work_unit_id`、需求/代码版本和环境，并至少记录：

- `goal_id`、目标行为或风险、测试预言机和退出条件；
- 已测范围、未测范围、数据/夹具和测试资产；
- 本轮质量指标的测量口径、推荐值、用户指定值（如适用）和最终采用值；单测覆盖率 Goal 额外记录临时启用的 JaCoCo 配置、实际结果和未覆盖范围；
- 证据、观察时间、残余风险及下一行动。

Goal 是剧本内工作单元，不调用平台 Goal 工具，也不另建状态机。`work_unit_id` 汇总记录四项质量指标（单测覆盖率、关键路径覆盖、P0/P1 缺陷门槛、测试反馈时限）各自 Goal 的测量口径、实际结果和采用结论；P0/P1 只记录实际未关闭数与处置结论，不接受阈值放宽。

## Goal 建立

从用户任务和验收标准建立或复用 `work_unit_id`，再建立当前质量指标的 Goal，写明目标行为或风险、测试范围、环境、退出条件和本轮唯一的主指标。首轮以单测覆盖率为主指标，并临时启用 JaCoCo，明确覆盖率统计口径、范围和拟协商的阈值；后续 Goal 仅记录其对应指标。输入已足以确定测试时直接执行，只有环境、范围、覆盖率口径或判定依据存在会实质改变结论的歧义时才询问用户。

## 指标口径

| 指标 | 测量口径 | 通过条件 |
| --- | --- | --- |
| 单测覆盖率 | 当前代码范围内可执行行或分支的已覆盖比例；明确采用行或分支、排除项和本次报告。 | 达到本轮采用的百分比阈值。 |
| 关键路径覆盖 | 已确认关键场景清单中，实际执行且通过的场景数 / 场景总数。 | 清单中的场景全部通过，或按本轮采用的例外记录。 |
| P0/P1 缺陷门槛 | 当前版本、环境和测试范围内已确认且未关闭的 P0/P1 数量。 | 未关闭数量为 0；不得以用户指定值或风险接受放宽。 |
| 测试反馈时限 | 从触发必跑测试到产出可核验结果报告的耗时；排除已记录的人工等待时间。 | 不超过本轮采用的时限。 |

## 指标协商

固定对齐四项质量指标：单测覆盖率、关键路径覆盖、P0/P1 缺陷门槛和测试反馈时限。每项分别建立 Goal，不在同一回合合并协商。

- 每个可配置指标 Goal 开始时，结合当前需求、代码风险、历史证据和执行成本给出推荐值，并说明依据；
- 与用户对齐该指标。用户指定目标值时采用用户值；用户未指定时，采用推荐值继续执行测试。P0/P1 Goal 只与用户对齐影响范围、修复优先级和处置计划，未关闭数量必须为 0；
- 按单测覆盖率、关键路径覆盖、P0/P1 缺陷门槛、测试反馈时限的顺序处理，除非用户明确调整优先级。

## 测试设计

- 先核验开发单元测试证据，再选择能够独立覆盖剩余风险的最低测试层次；用例验证可观察行为。
- 用例彼此独立，Mock 仅用于网络、数据库、时钟等系统边界；测试名称表达预期结果。
- 版本、环境、数据或夹具变化后，旧证据只可作为历史参考；当前结论必须基于本 Goal 的当前输入重新执行。

## 执行闭环

1. 按已选测试层次由 `qa` 生成或更新正式测试资产。
2. 在绑定环境和数据边界内执行与本轮指标对应的测试，记录命令、结果、版本、环境和未覆盖范围；单测覆盖率 Goal 临时启用 JaCoCo，并记录覆盖率报告和实际覆盖率。
3. 对本轮可配置指标先给出基于上下文的推荐值，再与用户对齐；用户未指定目标值时，采用推荐值继续执行。P0/P1 Goal 不协商门槛，只对齐影响范围和处置计划。四项指标分别完成各自 Goal 的对齐；测试结束后撤销仅为单测覆盖率 Goal 临时启用的 JaCoCo 配置，避免将其意外固化到常规构建流程。
4. 发现不符合预言机的行为时，`qa` 登记 Bug：复现步骤、预期/实际结果、影响范围、版本、环境和证据齐全后交给 `dev`。
5. `dev` 返回修复说明后，`qa` 复测原复现及受影响范围，并独占决定关闭或重开 Bug。
6. Goal 退出时，按 `qa` 剧本输出 `pass`、`conditional` 或 `blocked`；测试结论不等同于发布结论。

## 禁止动作

- 不修改业务实现，不代替 `cr` 做代码、安全或数据审查。
- 不将未复现的猜测登记为 Bug，不用局部绿灯扩大验收范围。
- 不作发布预检、风险接受或最终 Go/No-Go 决定。
